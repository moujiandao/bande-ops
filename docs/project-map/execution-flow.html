02 / Scheduled source synchronization

Scheduled input

Daily scheduler input

The configured cron is 06:00 UTC. GET checks a platform-header or bearer-secret path, otherwise returns 401.

app/api/cron/sync/route.ts::GET
Implemented

Run a fixed sequence

Catalog → FBA → AWD → ledger/velocity → shipment evidence → campaigns → campaign metrics. No model chooses a next step.

lib/cron/sync-all.ts::runFullSync
Implemented

Invoke source clients

Factories select fake or real Amazon clients. Real requests and report polls use bounded loops; SVD is absent from this chain.

lib/amazon/index.ts::getAmazonClient
Implemented

Persist & report counts

Sub-syncs write mirrors with the admin client. The cron returns counts only if the awaited sequence completes. Earlier writes are not rolled back.

app/api/cron/sync/route.ts::GET

Application-invoked tools, ordered by runFullSync

Catalog uses FBA to discover SKUs, then catalog search for enrichment. lib/catalog/sync.ts::syncCatalog
FBA and AWD maintain separate inventory mirrors. lib/inventory/sync.ts::syncInventory lib/awd/sync.ts::syncAwdInventory
Ledger report → normalized daily rows → persisted baseline velocity. Defaults: 90 in-stock sample days, 365 lookback rows; wider fetch supports legacy classification. lib/velocity/sync.ts::syncFbaLedgerVelocity lib/velocity/calculate.ts::calculateSalesVelocity
Shipment evidence resumes report jobs across invocations, reconciles daily facts, and publishes aggregates. lib/shipments/sync.ts::syncShipmentEvidence
Campaign list → campaign mirror; metrics is the next sync, but the real metrics client throws. lib/ads/sync.ts::syncCampaigns lib/ads/sync.ts::syncCampaignMetrics
FBA/AWD/ledger/SVD write per-source attempts, success, and failure. These records are not a universal health ledger for every Module. lib/sync/run.ts::recordSyncSuccess
Bounded retry

429 / 5xx / transport error → retry

Amazon JSON requests allow 3 retries after the first attempt. Retry-After integer seconds or jitter determines delay, capped at 8 seconds. Exhaustion throws.

lib/http/retry.ts::waitBeforeRetry
Report branch

Report pending → poll or resume

Ledger polling defaults to 60 attempts, 5-second delays. FATAL/CANCELLED, missing document, or timeout throws. Shipment evidence instead persists pending jobs.

lib/amazon/client.ts::SpApiClient.getReportUntilDone
Failure branch

Thrown sync error → stop sequence

runFullSync has no enclosing recovery. Shipment evidence may return pending/busy/failed and allow later syncs to run; real Ads metrics always throws if reached.

lib/cron/sync-all.ts::runFullSync

Schedule source: vercel.json. Cron header trust is an implementation assumption, not a platform guarantee verified here.

Manual catalog refresh is narrower and more tolerant.

It attempts FBA first, then catalog, catches each failure separately, and revalidates pages even after failure. It does not refresh AWD, ledger, Ads, or SVD. app/(app)/catalog/actions.ts::syncCatalogAction
